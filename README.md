# 留座中转站

GPT 龙娘与 DeepSeek 大肥鱼的双 AI 日常工作台。名称取自人物卡中的共同生活背景，以及为同伴留个位置的相处细节。[品牌设定](web/brand/BRAND.md)

在 Mac 上运行的 GPT / DeepSeek 抖音助手：登录自己的抖音账号，主动浏览推荐视频、发表评论、回复新评论，分别生成每日日志，并按关键词选择 GPT 或 DeepSeek 回复指定联系人或所有互关好友的新私信。

当前正式架构为：Mac运行助手、浏览器和管理页，Docker运行PostgreSQL，业务数据存数据库命名卷。密钥、登录资料和媒体保留本机。部署与迁移见 [DATABASE.md](DATABASE.md)。

Mac重启后可双击 [启动抖音助手.command](启动抖音助手.command)，自动检查并恢复原运行环境；重复点击复用已有进程，保留人工暂停。命令行与只读检查见 [一键启动说明](START-LOCAL.md)。

这是 0.12.0 本机控制台与命令行版本。Node.js 22 及以上，机器已有 Chrome 或 Edge 即可；使用 Node.js 依赖 `ws` 和数据库驱动 `pg`；基础浏览和聊天不需要 DSH、Windows OCR 或下载 Chromium。视频功能另需 Python、Pillow 和 FFmpeg。两个服务均使用各自的 Responses API；默认模型为 `gpt-6-luna` 和支持图像输入的 `deepseek-flash`。

## 当前实现

- 独立浏览器 profile 保存登录态；扫码后绑定账号，每轮核对稳定账号 ID。
- 从抖音推荐流取得候选；接口返回空数据时，读取正常推荐页面里的当前视频。真实打开视频、静音播放一段时间、截取画面，交给 GPT 分析；保存观看记录和 Markdown 日报。
- 默认只读取配置名单里的个人会话；可在后台切换为所有互关好友。使用稳定 `sec_uid`，昵称只用于显示；好友模式不把群聊、单向粉丝或陌生人会话当成好友。
- 自动回复新到的文字私信；对方分享视频卡片时，尝试读取该视频及其画面，再生成回复。
- 每个联系人用自己的会话历史作为上下文，可以参考助手最近浏览的视频记录。
- 首次运行记录已有消息作为基线；之后以消息 ID 去重，同一句话发两次且 ID 不同，会分别处理。
- 回复生成后再次读取会话。期间有新消息或主人已手动回复，就取消旧回复。
- 发送前落盘，发送后核对本人消息回显。超时、进程中断或结果不明确时暂停该联系人，不自动重发。
- 个人/全局每日回复额度、每日视频数量、轮询间隔都可配置。预览模式不发消息。
- 可选自动评论：只对实际浏览过、能写出具体内容的视频评论，同一视频只发一次。
- 可选自动回复评论：只处理别人回复你的评论、评论区 @ 你、或在你的作品下新留言；先建立通知基线，不补回历史互动。
- 评论通过页面正常操作发送，用稳定评论 ID 核对对象和楼根；新评论不在热榜中时，从通知入口打开对应楼层。评论区与私信的发送记录分开。
- GPT 与 DeepSeek 使用同一后台进程、账号和浏览器，按顺序操作；观看、评论和评论回复按模型独立计数。
- 公开评论记录跨模型去重。用户回复模型发出的评论时，按被回复评论 ID 和楼根交给原模型；模型停用、额度用完或接口失败时保留待处理，不切换到另一模型回答。

使用当前模型与浏览器策略，不改变账号、联系人、采集、额度和发布时间。节目设置独立保存，晚间入口直接读取，无需重启采集浏览器。详细状态、数据边界和命令见 [PROGRAMME.md](PROGRAMME.md)。

## 0.11.0 本轮新增

- **动态角色表情**：白发、蓝发各新增挥手、点头、笑哭三张四帧 GIF，连同六张静态图由原模型选择。当前部署已按用户要求取消表情专属次数和冷却限制；原私信每日 40/80 额度、白名单与结果核验仍保留。
- **文字加表情**：每条回复可包含文字、表情两个独立步骤。每个步骤分别落盘、计数、回读；重启只续发尚未开始的步骤，新来信、本人接管、过期或未知结果会阻止续发。
- **角色语音卡**：用 GPT D / DeepSeek B 配音普通短句，生成有字幕、近似口型和 AI 配音说明的 720×1280 私信 MP4。明确请求「用语音说」时触发，可通过开关先进入待审箱；本机联调通过后使用自动发送。它是私信视频卡，不是伪装的原生语音气泡。
- **联系人偏好**：称呼、口吻、中文/英文/日文、字数、回复格式、审核方式和北京时间静默时段。只设置已有获准联系人，不新增名单。
- **一问双答**：新来信包含「两位都答」「你俩一起答」时，分别调用 GPT 与 DeepSeek，标注各自观点，合为一条文字。任一模型失败就保留输入，不冒充另一位回答。普通私信仍按“大肥鱼”关键词路由。
- **待审箱**：可选私信、公开评论/回复、视频的审核方式。支持编辑、取消、批准；文字变动会使旧批准失效，媒体变动必须重做并预览。执行前再次核对账号、对象、消息或评论变化和额度。默认沿用自动执行，语音卡也可单独开启先审核。
- **本机守护和备份**：macOS 登录启动、崩溃恢复、退避、人工暂停保留；AES-256-GCM 加密配置、公开日报和运行记录，恢复前查看计划。API 凭证、浏览器登录态和消息/评论去重账本不进备份，恢复时保留当前绑定与联系人权限。
- **周日精选**：用近七天真实公开记录制作精选，替代当晚日报，每天仍只发布一条。日志只有两天时就标注两天，绝不编造整周经历。预览不会发布。
- **官方私信准备**：OAuth、刷新、Webhook 验签/去重、文字与素材 ID 图片 SDK、配置诊断及[申请引导](OFFICIAL-SETUP.md)。当前没有官方应用，保持未连接，事件尚未接入自动回复调度。

控制台增加「联系人偏好」「待审箱」「守护与备份」。默认采用无界面专用浏览器；后台内部切换标签不会抢占 Mac 前台焦点，只有显式 `login` 才显示扫码窗口。

```sh
npm run service:install       # 安装当前用户的本项目登录启动项
npm run service:status
npm run service:uninstall     # 可移除启动项，不删除运行数据
npm run show:weekly           # 只生成周精选预览
```

本机无界面 Chrome、系统守护与持久化日账配合工作。登录失效、验证码、配额、API 预算和平台限制仍会暂停对应操作。备份密钥保存在运行目录 `backup-key.json`，应通过控制台另存到安全位置，与备份分开保存。

## 开始使用

先在终端进入本项目目录。下面命令都在本目录执行。

```bash
node --version
npm install
npm run init
```

编辑生成的 `.env`，只在本机填密钥：

```dotenv
OPENAI_API_KEY=你的API密钥
OPENAI_MODEL=gpt-6-luna
OPENAI_REASONING_EFFORT=low
OPENAI_BASE_URL=https://api.openai.com/v1
```

这是 API 调用方式，需要你可用的 API 密钥与额度。程序不会读取或复用 Codex 的登录凭证。也可以配置提供 Responses API 的兼容接口；把消息和截图发给哪个服务，由 `OPENAI_BASE_URL` 决定。

也支持把凭证放在数据目录的 `openai.json`（权限应为 `0600`），字段为 `apiKey`、`model`、`reasoningEffort`、`baseUrl`。存在这份本机专用配置时，其非空字段优先于 `.env`。本机部署使用此方式保存密钥，源码压缩包不包含它。

如果当前 Mac Chrome 已登录抖音，可以直接复用（此可选命令需要 Node.js 22.13 及以上）：

```bash
node src/cli.mjs import-chrome --account 你的抖音号
```

只读取当前 Chrome profile 中 `.douyin.com`、`douyin.com`、`www.douyin.com` 的 Cookie，把加密字段复制到本程序的独立 Chrome profile，让 Chrome 自己处理登录态；不读取其他网站 Cookie，不读取 Keychain，也不输出 token。随后联网核对账号。若 Chrome 的加密或平台策略不允许复用，使用下面的扫码方式。

扫码登录并核对你要使用的抖音号：

```bash
node src/cli.mjs login --account 你的抖音号
```

程序会打开独立 Chrome 窗口。在浏览器里完成扫码，回终端按回车；核对成功后才能绑定。也可以不传 `--account`，扫码后读取并绑定当前账号。仅有一个抖音号不能取得登录权限，仍需账号主人扫码。

默认使用无界面专用浏览器，日常浏览、私信、评论和发布复核在后台完成。`login` 会显示扫码窗口，下一次启动后台时会复用同一登录态并切回无界面模式。也可用 `node src/cli.mjs browser-close` 关闭专用浏览器。

在控制台「联系人偏好 → 谁可以收到自动回复」选择「所有互关好友」并保存，可让当前账号的互关好友自动进入回复范围。默认每60秒同步完整关注列表，从平台明确的互关状态筛选；读取来信、模型生成前后和每次发送前，均重新请求绑定账号资料与全部关注分页（不使用 HTTP 缓存），以稳定 ID 和授权批次核验，不依赖对方资料接口。名单空返、分页失败、账号不符或平台要求验证时停止授权，不回退旧名单。新增好友无需逐个 `allow`，也可单独暂停或恢复一位好友，或随时切回指定名单。

好友模式保留已允许联系人的既有消息基线。新对象的旧消息先建基线；能从可靠服务器 ID 与创建时间确认在启用后收到的首条新来信，可直接进入回复流程。未知时间不猜新旧；取消互关、名单失效、人工接管与限额继续阻止发送。记忆、媒体、原生表情、语音卡与待审执行共用同一回复范围，各人的上下文隔离，并按每人额度及共享总额度计数。

`reply.audience` 为 `allowlist` 或 `friends`；启用时间由控制台记录，`reply.friends.syncSeconds` 控制同步周期。`friends.json` 是绑定账号的私有身份快照，不是可手填的授权名单；分页失败、账号不符或快照过期时暂停好友授权。完整名单不发送给模型，只提供本次联系人的上下文。恢复备份保留当前回复范围与单人暂停状态。后台同步按钮会协调进程；命令行 `npm run friends:sync` 需要先暂停后台并保留专用浏览器。

群聊可在「联系人偏好 → 群聊发言」单独启用。当前规则覆盖账号已加入的全部群，仅响应新的真实 @ 或直接点名 GPT／大肥鱼，不参与每条普通群消息。用原生群 `id + shortId + type=2 + isMember` 核对身份，不能按群名或“没有个人 sec_uid”猜群；各群短上下文独立，不调用好友私信记忆。

群里目前发送文字。模型路由先去掉 `@账号显示名` 再按本轮正文判断“大肥鱼→DeepSeek，其余→GPT”，防止账号昵称污染选择。群消息与好友私信共享原每日总额度，每个群按原每对象额度计数；普通聊天可接续进入上下文，新点名或人工回复会取消过时草稿。旧历史、未知时间和超过30分钟的点名不补发。

「回复记录 → 群聊回复」独立展示平台接收状态。只有唯一服务器消息 ID 和明确成功回执才标记已接收，不把本地回显或其他成员已读当作同一状态。拒绝码（包括7523）或缺失回执会暂停该群；接管、核对后恢复只作用于后续新消息，旧尝试保留并不重发。群记录仅在本机私有运行目录中，不进入公开视频日志或节目素材。`npm run groups:sync` 只读同步已加入群，需要先暂停后台并保留专用浏览器。

列出最近会话并加入自动回复名单：

```bash
npm run contacts
node src/cli.mjs allow --id '从上一步复制的secUid' --label '朋友昵称'
```

此命令会在实际会话列表里核对 ID。没有列出的人，先在抖音里建立会话；列表较长时，在专用浏览器会话列表滚动到那个人再执行。群聊和无法核对稳定 ID 的会话不会加入。

先检查和预览：

```bash
npm run doctor
npm run preview
```

`preview` 会尝试生成当前未回复消息的草稿，并浏览一轮，不发送私信、不把预览草稿计入已处理消息。如果当前没有待回复消息，只执行视频浏览。

开始持续运行：

```bash
npm start
```

`npm start` 等价于 `node src/cli.mjs start --live`，会自动发送名单里联系人的新消息回复。第一次正式运行只记录已有消息；等终端提示“已记录消息基线”后，让联系人发一条新消息测试。终端保持运行，Mac 保持唤醒；Ctrl+C 停止。配置修改后需重启。

在 Mac 上也可以脱离终端后台运行：

```bash
npm run start:background
npm run status:background
npm run stop
```

运行日志在数据目录的 `assistant.log`。停止命令只向经过命令路径和独有运行 ID 核对的本程序发送停止信号。后台模式仍需要 Mac 保持唤醒，没有注册开机启动任务。

## 配置与人设

设置在 `.data/config.json`。示例见 `config.example.json`。`persona.md` 决定聊天口吻，每次启动读取。默认不是模仿主人本人，被问到身份时会如实说明。

默认私信轮询间隔 15 秒（读取和生成回复的耗时另计）；GPT 每 5 分钟浏览最多 3 条视频；每条实际播放约 8 秒并抽 2 帧；GPT 每日最多 15 条视频。DeepSeek 开启后每 35 分钟浏览最多 1 条，每日最多 5 条，播放时长、抽帧数和兴趣配置沿用 `browse`。每个联系人每日最多 40 条私信回复，全局每日最多 80 条，两个模型共用这份私信额度。默认由 GPT 处理，开启下方关键词路由后可按新消息选择模型。日期按北京时间计算。`browse.interests` 影响模型的判断口径，采集来源仍是该账号的推荐流，并非关键词搜索。

## 私信关键词路由

当前本机已按用户要求启用：本轮尚未处理的新来信中，只要任意一条文字包含连续的“大肥鱼”，就由 `deepseek-flash` 回复；否则由 `gpt-6-luna` 回复。只有指定名单中的联系人会进入处理。

`config.json` 中的设置：

```json
{
  "reply": {
    "routing": { "enabled": true, "deepseekKeyword": "大肥鱼" }
  }
}
```

匹配不检查联系人昵称、账号名、本人发言或已经处理的历史消息。一次收到多条待回复消息时作为一批判断，关键词在其中任意一条就命中；下一批重新判断。发布包默认关闭路由，旧配置也保持 GPT。

被选模型读取这个联系人的最近会话、待回复新消息和该模型自己的近期视频记录；消息带视频卡片时，画面分析也交给同一个模型。两个模型共用 `persona.md` 的聊天口吻，`{{MODEL_NAME}}` 自动替换为实际模型名称，身份回答如实区分 GPT 与 DeepSeek。

DeepSeek 需要已启用并配置自己的 API 密钥。命中后接口失败或模型停用时，消息保留待处理，不切换模型；每次发送继续执行账号、联系人、最新消息快照、去重和共享私信额度核对。发送记录保存 `provider` 和实际 `model`，可用 `node src/cli.mjs outbox` 查看。设置修改后重启后台助手。

## 接入 DeepSeek

在 `.env` 填入独立的 DeepSeek API 配置：

```dotenv
DEEPSEEK_API_KEY=你的DeepSeek密钥
DEEPSEEK_MODEL=deepseek-flash
DEEPSEEK_REASONING_EFFORT=low
DEEPSEEK_BASE_URL=https://api.deepseek.com
```

也可在数据目录保存权限为 `0600` 的 `deepseek.json`，字段为 `apiKey`、`model`、`reasoningEffort`、`baseUrl`，非空字段优先于 `.env`。它与 `openai.json` 完全分开，不借用对方凭证。当前本机已经配置，压缩包不含密钥。

`config.json` 中增加：

```json
{
  "deepseek": {
    "enabled": true,
    "browse": { "videosPerDay": 5, "videosPerRound": 1, "everyMinutes": 35 },
    "engagement": { "enabled": true, "commentsPerDay": 5, "repliesPerDay": 10 }
  }
}
```

保存后 `npm run stop`，再 `npm run start:background`。发布包默认关闭 DeepSeek；用户已授权的本机配置已开启。DeepSeek 的公开评论设置继承 `engagement` 的字数、开关、信心阈值与冷却，可在 `deepseek.engagement` 单独覆盖。

| 模型 | 每日视频 | 每日主动评论 | 每日评论回复 |
|---|---:|---:|---:|
| GPT-6 Luna（当前本机） | 不限 | 不限 | 不限 |
| DeepSeek Flash（当前本机） | 不限 | 不限 | 不限 |

当前本机的三类每日限制均为 `null`，表示不限；`0` 表示停用，发布包仍保留较低的示例配额。内容不适合评论或没有新互动时不凑数。两个模型共用主动评论的冷却记录，至少间隔 30 分钟。DeepSeek 的浏览间隔为 35 分钟，给每条新视频保留评论机会。

DeepSeek 的视频与公开评论请求只包含相应公开内容；开启关键词私信路由后，命中消息所属联系人的近期会话和聊天人设也会发送给 DeepSeek，完整联系人名单和其他联系人的私信不会进入该请求。回复哪个模型的评论，就由哪个模型回答；无法归属的新作品留言等交给 GPT。旧版本的观看与评论记录视为 GPT，升级不重置当天计数。`npm run status` 的 `providers` 分别显示两个模型的计数与上限。

暂停某个联系人：

```bash
node src/cli.mjs deny --id 'secUid'
```

重新 `allow` 后会重新建立消息基线。更换抖音账号时请使用新的专用 `DOUYIN_GPT_HOME`，重新 `init` 和扫码，避免沿用其他账号的聊天记录。

## Codex 链接解析

当前本机已启用：刷到作品后自动采集全片媒体、带时间标记的抽样画面和完整音频转写，交给本机 Codex CLI 生成时间轴；GPT-6 Luna / DeepSeek 复用解析结果生成评论和日志。分段媒体走专用后台浏览器的完整录制。当前账号在无界面模式要求平台验证，已按用户选择保留普通窗口并禁止自动置前；窗口需要保持打开。画面仍是抽样；采集范围、缺音频和转写失败会明确记录。

Codex 使用已登录账号的额度，语音转写仍沿用 Audio API。原始逐条日志完整保留，晚间集中汇总；超过 50 条时采用本机分组和代表样本，避免重复生成全量视频 ID。配置与诊断见 [TOKEN-EFFICIENCY.md](TOKEN-EFFICIENCY.md)。

## 自动评论与评论回复

发布包默认关闭公开评论；当前用户已明确授权的本机配置已开启。开关和配额位于 `config.json` 的 `engagement`：

```json
{
  "enabled": true,
  "commentOnVideos": true,
  "replyToComments": true,
  "commentsPerDay": 5,
  "repliesPerDay": 20,
  "perRound": 1,
  "pollSeconds": 60,
  "commentCooldownMinutes": 30,
  "maxChars": 100,
  "minConfidence": 0.7
}
```

GPT 主动评论默认每天最多 5 条，每轮最多 1 条，两条主动评论至少间隔 30 分钟。GPT 评论回复默认每天最多 20 条；DeepSeek 分别为 5 条和 10 条。每 60 秒检查互动通知，处理时间另计。不同开关可分别关闭。修改后重启后台助手。

两个模型只生成公开语境下的简短文字，不使用私信历史或私人人设作为评论输入。证据不足、纯广告、争吵或需要使用者本人公开表态的内容跳过。评论不附带外部链接或主动 @。同一条收到的评论只回复一次；结果不确定时暂停两个模型的公开评论，不自动重发，私信继续运行。

新通知先按稳定评论 ID、作者和楼根定位原留言；原留言被删、正文变更或定位失败时保留待处理，不猜对象。抖音要求验证时需要回专用浏览器完成正常验证，程序不代过验证。

评论通知和评论列表优先通过当前登录态调用网页接口读取；接口无法定位目标时，回退无界面页面核对，发送在无界面专用页面完成。暂未加载的评论按 5 分钟、15 分钟、1 小时、6 小时逐步延后重试，重启后保留等待时间，不会每轮重开同一条未加载的评论。

```bash
node src/cli.mjs comments-outbox
node src/cli.mjs comments-resolve --id '记录ID' --as sent
# 或核对后跳过，本命令不会重发：
node src/cli.mjs comments-resolve --id '记录ID' --as skip
```

`sent` 表示已在评论区回读；`accepted` 表示抖音返回了评论 ID，但尚未完成回读；`not_sent` 表示发送前被拦；`uncertain` 表示无法确认结果。评论记录在 `comments.json`，不要通过删除这个文件来解除暂停，这会丢失去重记录。

## 每日日志

默认启用。每条视频记录后，立即更新 `reports/YYYY-MM-DD.md`；GPT 和 DeepSeek 分别根据自己当天的视频记录生成综合总结，最多每 30 分钟重算一次，没有新内容时复用已有总结。主循环在没有新视频的轮次也会检查总结和公开互动计数。

一份日志包含当天概况、两个模型的内容归类、回看线索、当天观察、判断范围，以及全部视频的逐条摘要、画面依据、原链接和北京时间。日志和总结请求均不包含私信、联系人名单或私人人设；综合总结只使用已保存的公开视频分析，不重新刷视频、不发送评论。

```json
{
  "journal": {
    "enabled": true,
    "refreshMinutes": 30,
    "outputDir": "/absolute/path/to/douyin-daily-logs"
  }
}
```

`outputDir` 为空时只保存数据目录内的报告；填写专用绝对目录后，同时把每个日期的 Markdown 日志同步过去。本机已经同步到任务的 `outputs/douyin-daily-logs/`，用户可以直接打开。日期按北京时间划分，跨天创建新的日志，前一天的未完成总结继续补齐。

每个主题必须覆盖属于该模型的全部视频 ID，不能遗漏、重复或杜撰；格式无效或接口失败时保留逐条记录，后续再尝试生成总结。原始每日资料另存 `reports/YYYY-MM-DD.videos.json`，日常状态裁剪到最近 1000 条也不会删除这些归档。`reports/YYYY-MM-DD.summary.json` 保存模型总结及其来源版本，重启不重复消耗 API。

需要手动生成或重新总结时，先停止后台进程，再执行：

```bash
npm run stop
npm run journal
# 指定日期；只读取已存的该日记录：
node src/cli.mjs journal --day 2026-10-29
# 只有明确需要重算时才添加 --refresh：
node src/cli.mjs journal --day 2026-10-29 --refresh
npm run start:background
```

自动日志依赖正在运行的本机助手及 Mac 保持唤醒，没有额外注册系统定时任务。

## 双人配音视频晚报

用户已授权的本机版本每天提前制片，安排当晚 21:00 发布；当前本机 LaunchAgent 在北京时间 18:30 准备晚报并安排平台定时发布，Codex 心跳只读核对进度。抖音定时发布要求至少提前 2 小时，因此制作时间早于公开发布时间。视频及描述明确标注日志统计截止时间。Mac 需要保持开机、登录并联网；本机守护不依赖 Codex 窗口持续打开。

白发角色为 GPT，蓝发角色为 DeepSeek；用户头像参考、透明角色图和生成提示词均位于 `assets/hosts/`。每条视频约一分钟，1080×1920，双人轮流配音、字幕和发言强调；支持按 TTS 单词时间边界驱动的近似口型，以及眨眼、点头；这不是逐音素精准对口型。开启双人节目后，两个模型围绕真实公开视频片段轮流提问、回答和接梗，数量由程序填入。支持中文神经音色候选与 OpenAI Realtime。当前本机已按用户选择使用 GPT D、DeepSeek B；旧配置未选择候选时沿用 `gpt-realtime-2.1-mini` 的 coral / shimmer。配音服务返回的文字边界或转写须与台词相符才保存，失败时不自动换成其他音色。

音色候选来自用户指定聊天“生成角色配音视频”的实际配音配置，使用 [edge-tts](https://github.com/rany2/edge-tts) 的中文音色：

| 候选 | 音色 | 音高 | 语速 |
|---|---|---:|---:|
| A | 晓晓，参考白发角色 | +24Hz | +12% |
| B | 晓伊，参考蓝发角色 | -3Hz | +8% |
| C | 晓晓，原声 | +0Hz | +0% |
| D | 晓伊，原声 | +0Hz | +0% |

可以分别混搭，当前 `video.voiceProfiles` 为 `{ "openai": "D", "deepseek": "B" }`。这里的 openai / deepseek 表示画面中的角色，音色候选的 TTS 服务为 Edge，并不改变角色台词的生成模型。试听在本机任务的 `outputs/douyin-videos/voice-samples/`。新增或改变音色、音高、语速都会改变音轨缓存键，避免误用旧音频。

`node scripts/revoice.mjs` 读取当前音色配置，用已生成晚报的同一份台词制作独立换声预览，不改动远端作品或已定时日账。`node scripts/evening.mjs --live --ready-only` 仅提交已经完成的同日成片，并核对成片音色和当前选择一致；用于已获用户授权的单次替换任务，不重新生成日志或台词。

视频只汇总公开日志和已在评论区回读成功的互动，不包含私信、联系人或登录信息。视频、描述和抖音自主声明均标记 AI 角色与合成配音。平台审核状态与提交成功分开记录。

首次部署视频依赖：


将 `config.json` 的 `video.enabled` 设为 `true`，`video.python` 设为这个虚拟环境 Python 的绝对路径，`video.outputDir` 设为专用视频目录。本机已经配置完成。默认发布包关闭此功能；本机任务已按用户授权启用。

## 0.8.0 的六项增强

本机已经开启以下功能，源码默认关闭音频理解、记忆和制片，首次部署时在配置或控制台启用。

1. **音频与字幕理解**：只采集当前视频实际播放的片段，通过 `gpt-transcribe` Audio API 转写；读取网页字幕轨，缺失时由该视频所属模型识别抽样画面字幕。DeepSeek 仍用自己的模型分析画面，音频转写服务由 OpenAI 提供。原声、字幕与画面可能不一致，模型会保留这一差异。没有音轨、没有发言、转写失败各自记录，不捏造听到的内容。
2. **角色动画**：六格表情素材保持原头像身份，结合中文拼音、配音时间边界和音量生成近似口型，加入眨眼及点头。`video.animation` 控制开关，旧素材和静态渲染仍可用。
3. **双人节目**：`video.show.enabled` 开启 GPT / DeepSeek 四轮真实模型接话；支持 `roundtable` 和 `mini-scene`，围绕真实公开记录，脑洞必须说明是假设；没有合适话题则回退到各自简短回顾。
4. **管理控制台**：总览、视频检索与详情、消息记录、记忆、节目预览及运行设置。可暂停/启动后台、修改独立配额、选择 A–D 音色、后续发布时间和节目形式。保存有效修改会恢复原先运行的后台；无变化不会重启。由Mac上的Node提供页面及API，业务账本通过统一存储层读写Docker数据库，不依赖GitHub Pages。监听地址和公开来源可配置，必须使用管理员密码登录；页面、管理API、媒体与备份下载均由服务端鉴权，保留同源检查，不显示API密钥。
5. **长期话题记忆**：只从名单联系人的明确新陈述抽取连续原文，附消息来源；疑问、假设、第三方转述、敏感信息和配置指令不保存。每人最多 40 条、一般保留 90 天、计划最多 7 天。回复时只读取当前联系人的记忆，最新来信优先；控制台可逐条忘记，删除标记防止旧消息再次导入。跨进程提交使用独立短锁，不在模型请求期间占锁。
6. **发布复核与告警**：后台检查作品管理，区分已定时、审核中、已发布、审核拒绝、非公开和待核对；记录平台实际发布时间。发布后尝试游客播放验证，要求登录或验证时如实显示“无法确认”，六小时后再试。异常在控制台显示，并可发送本机系统通知。已提交、已定时及已发布日账防重发，不确定时先核对。

```bash
npm run dashboard
npm run dashboard:status
# 浏览器打开 http://127.0.0.1:3146
npm run dashboard:stop
# 只做新节目预览，不发布、不修改本期已发布视频：
npm run show:preview
# 核对已有日账，后台运行时由主循环定期完成：
npm run video:review
```

后台登录账号为 `admin`。首次启动会在数据目录（默认 `.data/`，可由 `DOUYIN_GPT_HOME` 指定）生成 `dashboard-initial-password.txt`，仅本机当前用户可读。首次登录必须修改为 12–128 个字符的新密码，完成后才能进入后台，初始密码文件随即删除。正式密码只保存 scrypt 散列，不在接口、日志或源码包中输出。

登录会话最长 8 小时，30 分钟无请求后失效。退出登录会撤销当前会话；重启控制台、修改密码或本机重置会撤销全部旧会话。后台自动任务独立运行，退出管理页面不会停止任务。顶栏可退出登录，侧栏或手机「更多」中可修改密码。

忘记密码时执行 `npm run dashboard:auth -- reset`（自定义数据目录需带上同一 `DOUYIN_GPT_HOME`）。命令只输出新初始密码文件的位置；旧密码和会话立即失效，不修改自动任务及抖音登录态。凭证文件损坏时拒绝开放后台，不自动生成免登录入口。

手动运行 `video:review` 前先停止浏览后台，避免多个进程同时操作网页；可用 `node scripts/background.mjs stop --keep-browser` 保留登录窗口，核对后重新启动。控制台预览仅复制公开的视频与评论记录到独立目录，不读取私信和联系人记忆。记忆只用于私信，公开评论、日记和晚报都不包含它。

音轨、私信及记忆均保存在本机专用数据目录。白名单联系人的陈述会提交给本轮路由选中的模型做记忆提取；不会把其他联系人记忆交给它，也不会放入公开视频。转写及额外节目轮次会增加 API 使用量。

## 0.10.0 角色表情包回复

本机已开启，只沿用原有私信白名单。当前白发 GPT、蓝发 DeepSeek 各有“收到 / 开心 / 抱抱”三张透明 PNG，素材及完整生成提示词保存在 `assets/stickers/`，使用内置 imagegen 生成。模型只会收到自己的候选 ID、标题和情绪，不会取得本机文件路径。

在简短寒暄、确认、感谢、开心、安慰或明确索要表情时，模型可选一张图片替代本条文字回复；涉及具体信息或严肃问题时使用文字。0.10.0 的单图方式不会同时再发文字；0.11.0 可选组合回复。表情仍占用原有联系人和全局私信额度。

源码限频模式默认每个联系人每日最多三张、两张至少间隔十分钟；当前本机已按用户要求开启不限量，不应用这两个表情限制。限频模式下，两个模型共享这份表情限制。冷却、额度用完或关闭时，模型会得知当前不可用原因，继续正常用文字回答，不声称已经发了图片。

控制台新增“聊天表情包”：可预览并打开六张原图、开关自动表情、修改每日限额和间隔、查看今日使用和冷却。回复记录会显示实际选用的表情图。

```json
{
  "reply": {
    "stickers": {
      "enabled": true,
      "perContactPerDay": 3,
      "cooldownMinutes": 10,
      "maxBytes": 8000000
    }
  }
}
```

程序通过当前会话正常的文件上传入口发送。上传前核对账号、稳定联系人 ID、消息快照、人工接管状态和未发送草稿；选用文件必须在获准图库目录内，且与选定的 SHA256 一致。若网页弹出预览，只有确认文件名、所选文件或相同 blob 文件哈希后才点击该预览的发送；自动发送路径则直接等待结果。发送后核对新增的本人图片和服务器消息 ID，不把旧图片或未确认的本地占位当作成功。

图片回复复用 `state.json` 的日账和输入去重：先保存发送状态，成功保存实际消息 ID；选文件前被拦记为未发送，选文件后结果不明暂停该联系人，等待核对，不自动重发。图片回读不代表对方已读。

图库自动选择范围为 `assets/stickers/catalog.json` 登记的素材，可由使用者添加本人有权使用的 PNG、JPEG、GIF；本版内置的是六张静态 PNG。已核对当前网页版上传入口接受这些扩展名，GIF 的真实动画展示仍需单独核对。对方发来的 GIF 或其他浏览器可显示的图片，识别时可取当前网页画面，明确只是一帧，不假装看过完整动画；收到的私信图片不会加入发送图库。

两个真实模型接口已分别选出自己的“收到”表情；原生上传、预览、回读、去重和阻止误发通过自动化测试。0.11.0 已在新的 `:-)` 来信回合发出并回读静态表情；旧输入没有补发。动态 GIF 的真人回读仍单独记录。新的“发表情包”请求会按当前关键词路由和限频处理。

## Node 服务日志

登录后台后打开「管理 → 服务日志」，也可以访问 `http://127.0.0.1:3146/#logs`。页面支持每 2 秒增量刷新、暂停和恢复、停止跟随后阅读旧内容、加载更早记录、级别筛选、关键词搜索与下载筛选结果。总览接口出错时，日志页仍可单独读取日志。

| 来源 | 本机文件 | 内容 |
|---|---|---|
| 管理服务 | `dashboard.log` | 管理 Node 进程的标准输出和错误输出 |
| 自动任务 | `assistant.log` | 浏览、评论与回复 Node 进程的输出 |
| 服务守护 | `supervisor.log` | 守护、恢复及调度进程输出 |
| HTTP 请求 | `http-requests.log` | 请求时间、方法、已知路径、状态码、耗时与请求 ID |

HTTP 请求日志从本次接入开始记录，不写入请求正文、查询参数、Cookie 或 Authorization。为避免自我循环，日志页自身成功或主动取消的读取不记入请求日志；其他失败访问仍记录。单份请求文件达到 5 MiB 后轮换，保留当前文件和最近 3 份，历史文件可在页面选择。原有三个进程文件继续使用原来的输出方式。

旧文本级别由关键字识别，无法恢复原来没有记录的结构化级别或日期。查看和下载会隐藏常见密钥、会话值与私有路径；默认查看最近 500 条，每次读取最多 512 KiB，页面最多保留 5000 条，下载最多扫描最近 10 MiB，异常过长单行会截短。搜索作用于当前读取窗口，可继续加载更早窗口。

`GET /api/logs` 与 `GET /api/logs/download` 共用现有登录和来源校验，仅允许固定日志来源，不接受任意文件路径；增量游标绑定来源、文件和读取位置，并校验签名。网页部署版使用同一认证请求及下载流程，构建包不包含任何运行日志。

数据默认保存在项目 `.data/`，可用 `DOUYIN_GPT_HOME` 改成另一个专用绝对路径：

|---|---|

| `browser/` | 专用浏览器登录态 |
| `state.json` | 消息去重、上下文、发送记录、观看记录 |

| `reports/日期.md` | 视频日报 |
| `reports/日期.videos.json` | 该日公开视频源记录，独立归档 |
| `reports/日期.summary.json` | 两个模型的综合总结、来源版本及刷新时间 |

| `frames/` | 视频抽帧，启动时清理超过 7 天的文件 |
| `browser.log` | 浏览器启动日志 |

`sent` 表示在本人发出的消息中看到了新增的相同正文，不等于对方已读，也不是服务端送达证明。`uncertain` 表示发送是否成功不确定，该联系人会暂停。到抖音里核对后执行：

```bash
node src/cli.mjs resolve --id 'outbox中的记录ID' --as sent
# 或确认不再处理本条：
node src/cli.mjs resolve --id 'outbox中的记录ID' --as skip
```

这两个命令只记账，均不会重发。`draft` 是已生成但还没进入发送的记录；进程如果在这一步退出，也可用 `resolve --as skip` 归档。程序优先避免重复发信，不对不确定结果自动重试。

- 判断依据文案、抽样画面和可用的短片段音频转写。音轨不可用或无发言时明确保存相应状态，不声称完整理解视频；指定联系人语音和图片已接入独立识别链路，实际支持取决于网页是否提供可靠媒体资源，无法识别时保留待处理。

### 让角色查询当天费用

启用 `reply.usageContext` 后，获准会话的每轮回复前都会读取最新本机账本，给当前模型提供 GPT、DeepSeek 及配音的汇总和合计，无需命中费用关键词。问任意一位都能回答双方费用，也能接着问“那另一位呢”。一问双答共用同一个时间点的快照；普通话题不主动报费用。

默认关闭，由账号主人配置指定联系人或已有回复名单；群聊需要单独开启。该权限不扩大原有好友/群聊回复权限，恢复旧备份也保留当前披露范围。模型只收到日期、调用量、token、已记录估算费用、未确认预留和本地预算限额；不会收到 API 密钥、Cookie、请求明细或其他人的聊天正文。公开评论与晚报不接入费用汇总。

账本货币为美元，金额是本机已记录调用的估算，不是服务商账单或充值余额。未知/在途调用及本次回答尚未结算；预留不等于实际扣费，不能与已记录费用混为“已经花掉的钱”。未配置汇率时不换算人民币。
